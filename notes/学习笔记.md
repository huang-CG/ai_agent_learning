### 关键结论
1. **函数拆分**：`load/save` 管文件 · `add/delete/find/list` 管业务 · `main` 管循环
2. **列表 + 字典**：`contacts` 是列表，每个元素 `{"name": ..., "phone": ...}` 是字典
3. **`json.load` / `json.dump`**：Python 列表 ↔ JSON 文件；`load` 启动读，`save` 改完写

5. **`load_contacts()` ≠ 显示**：读文件不打印；显示要用 `list_contacts(contacts)`

- [x] 练习：命令行计算器 `exercises/day02/calculator.py`
- [x] 学会 Python 交互模式（`>>>`）与运行脚本的区别
- [ ] 拓展：10 道基础语法题（未做）

### 关键结论
1. **Python 缩进 = 代码块**：`def` / `if` / `while` 内的代码必须统一 4 空格，混用会 `IndentationError`
2. **`pass`**：占位符，函数/分支还没写内容时用，有真实代码后删掉
3. **切片 `[start:stop:step]`**：取列表一段，返回新列表，不改原列表；`stop` 不包含
4. **两种运行方式**：`>>>` 试小段代码；`PS>` 下 `python xxx.py` 运行完整脚本
5. **计算器题目本质**：`while` 循环显示菜单 → 用户选 1–5 → 读两个数 → 计算 → 直到选 5 退出

### 代码/实验
- 文件：`exercises/day02/calculator.py`
- 运行：`python exercises/day02/calculator.py`
- 结构：`show_menu()` 打印菜单 · `calculate()` 四则运算 · `main()` 循环调度

### 遇到的问题
- **没理解题目意思** → 菜单是数字 1–5，不是直接输入 `+ - * /`；要用字典把选项映射成运算符

- 缩进不一致（3 空格 vs 4 空格）→ `IndentationError`

### AI 指南 · 关键结论（第 1 章原文笔记）
Agent核心概念：
1.大模型是Agent的大脑，不同的模型拥有不同的参数规模、对话上限和处理能力
2.prompt(提示词)输入的质量决定Agent输出的质量，分为系统提示词和用户提示词，前者要提前设置约束Agent，后者自主输入
3.Token可以看作网络世界的价值单位，Token越多，成本越高，输出速度慢
4.API key:你在每个大模型创建的钱包
5.模型蒸馏：大模型难部署，将大模型知识浓缩转移到小模型，保持大模型性能，降低推理成本
6.解析上下文，获取更多的输出依据
7.RAG检索增强：提供外部知识库为Agent补充知识，其中用到Embedding嵌入
8.工具调用使Agent能力边界和应用范围无限扩大
9.CoT(思维链)和ReAct技术：一个将思考推理过程透明化，一个将思考->计划->推理->执行->推理流程循环化
10.智能体工作流：多Agent协同
11.MCP(模型上下文协议)统一Agent调用工具接口的标准
2. 第 2 章：市面上的Agent有很多，它们作用于不同的领域，我们只需按需取用
3. 第 3 章：使用Agent有很多技巧，学习技巧有助于我们更快更好地完成任务

### Agent 路线 · 5 个术语（已理解）

| 术语 | 一句话 |
|------|--------|
| **ReAct** | 推理→行动→观察 循环，Agent 最经典架构 |
| **Function Calling** | 模型输出 JSON 调用函数，程序执行后回传结果 |
| **Reflection** | 执行后自我审视，发现错误再迭代 |
| **Multi-Agent** | 多个 Agent 分工协作完成复杂任务 |
| **Execute** | Plan-and-Execute 中「执行计划」的阶段 |

### 什么是 Agent ✅

> Agent 是基于 LLM 的智能应用系统，能感知、推理、自主决策、执行命令。  
> **聊天机器人**：只会说，不会做。  
> **Agent**：会说也会做——思考、计划、调用工具、反思记忆、迭代优化。
