## D7 · API / 环境（入门）

**题 1**  
`load_dotenv()` 之后，`os.getenv("DEEPSEEK_API_KEY")` 取到的值最可能来自哪里？

- A. `chat.py` 里写死的字符串  
- B. `.env` 文件里的配置  
- C. DeepSeek 服务器返回的 JSON  
- D. `requests.post` 的响应头  

**答案：B**

**为什么选 B、不选其他**  
- **B ✅**：`load_dotenv()` 把 `.env` 键值加载进环境变量，`os.getenv` 再读取。  
- **A ❌**：Key 不应写死在代码里；写死也不需要 `load_dotenv`。  
- **C ❌**：服务器返回的是回答内容，不是你的本地 Key。  
- **D ❌**：响应头不含你本地配置的 API Key。

---

**题 2**  
`response.raise_for_status()` 在什么时候会抛异常？

- A. `response.json()` 解析失败时  
- B. HTTP 状态码不是 2xx（如 401、404）时  
- C. 网络超时时  
- D. API Key 写错时（无论状态码）  

**答案：B**

**为什么选 B、不选其他**  
- **B ✅**：该方法只检查 HTTP 状态码是否为成功（2xx）。  
- **A ❌**：JSON 解析失败是 `.json()` 抛的，与 `raise_for_status` 无关。  
- **C ❌**：超时通常在 `requests.post(..., timeout=)` 阶段抛，到不了或早于状态码检查。  
- **D ❌**：Key 写错常导致 401，本质仍是「非 2xx」；若请求没发出去则不是这个方法专门检测 Key。

## D8 · temperature / 幻觉 ✅

**题 1**  
`temperature=0` 时，同一问题多次调用，回答通常会怎样？

- A. 每次差很多  
- B. 几乎一样、很稳定  
- C. 一定更短  
- D. 一定更长  

**你的答案：B** ✅

**为什么选 B、不选其他**  
- **B ✅**：温度越低越「贪婪」、越确定，输出更稳定（工程上未必 100% 字节相同）。  
- **A ❌**：那是高温（如 1.2）更发散的表现。  
- **C ❌ / D ❌**：温度管随机性，不直接决定长短。

## D9 · system/user · HTTP404 ✅

**题 1**  
`messages` 里 `system` 和 `user` 一般怎么分工？

**你的答：** system 定规则（角色、格式、约束）；user 放内容；也可通过反复强调达成约束 ✅

**要点补强**  
- system = 岗位说明书 / 全局规矩（通常每轮都带）  
- user = 本次任务与待处理文本  
- 约束主要写在 system；user 里反复强调是辅助，不是替代

---

**题 2**  
HTTP 状态码 `404` 表示什么？

**你的答：** 客户端侧错误码；服务器已联通，但请求的资源不存在 ✅

**要点补强**  
- 4xx = 客户端侧问题；5xx = 服务器内部错误  
- 404 = Not Found：连上了服务器，但路径/资源找不到（常见 URL 拼写错误）  
- 对比：401 未授权、403 禁止、500 服务器错误

## D10 · CoT ✅

**Q1：** 为什么说 CoT 有时比降低 `temperature` 更有效？

**答：** temperature 管随机性（选词稳不稳），不教模型拆步骤；CoT 显式要求写推理链，中间步骤成为后续 token 的上下文，对多步题更有帮助。实践常 **CoT + 低 temperature**。

---

**Q2：** CoT 和格式约束的相同点、不同点？能否一起用？

**答：**  
- 相同：都是 Prompt 里的约束性指令  
- 不同：CoT 约束**推理过程**；格式约束约束**输出形态**（JSON、固定最后一行等）  
- 能一起用：例如「逐步思考 + 最后一行写：答案：鸡=X，兔=Y」

## D11 · 流式 ✅

**Q：** 流式相比非流式，用户体验和技术实现各改什么？

## D12 · 多轮（可选开放题）

**Q1：** 为什么说大模型「本身没有记忆」，但多轮聊天又能记得你叫什么？

**答：** 模型两次 API 请求之间不保存状态。「记得」是因为**你的程序**用 `messages` 保存历史，每轮把整段（含过往对话）再发给 API；模型从**本次请求的上下文**里看到以前说过什么。

---

**Q2：** `trim_history` 为什么一般要「永远保留 system，只裁旧的 user/assistant」？

**答：** 多轮会让 token 膨胀（贵、慢、易超窗口）。`system` 是整场角色与规矩，丢掉会行为漂移；裁掉**最旧的对话轮次**即可控长度，同时保留最近上下文。
