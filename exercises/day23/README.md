# Day 23 · Agent 记忆系统

## 这题要你做什么？（一句话）

> 给 ReAct Agent 加上**短期记忆**（多轮对话历史），让它能跨轮记住用户说的话——验收：**记住用户名字**。顺带搞清「长期记忆 / 向量库」是什么（概念即可，今天不写向量库代码）。

---

## 先抓住这一句

| 类型 | 是什么 | 今天做什么 |
|------|--------|------------|
| **短期记忆** | 当前会话的 messages 历史（同 D12） | ✅ 接到 ReAct 上 |
| **长期记忆** | 跨会话、可检索的知识（常靠向量库） | 📖 只理解概念 |

模型本身**没有记忆**：每一轮 HTTP 请求都是独立的。  
「记得」= 程序把**以前的对话**再塞进 `messages` 发给 API（D12 已练过）。

```text
D12：普通多轮 Chat + trim_history
D22：单轮 ReAct（每问一遍从零开始，不跨轮记名字）
D23：多轮历史 + 每轮内部仍跑 ReAct（scratchpad）
```

---

## 两层「记忆」别混

| 层 | 作用 | 生命周期 |
|----|------|----------|
| **对话历史**（短期） | 记住「用户叫小明」「刚才问过广州天气」 | 本次程序运行 / 本会话 |
| **scratchpad**（步骤本） | 记住本轮 Thought/Action/Observation | **一问之内**；下一问清空 |
| **向量库**（长期，概念） | 跨天、跨会话检索笔记/文档 | 持久化到磁盘/数据库 |

今天重点：**对话历史**。scratchpad 继续服务单轮 ReAct；向量库只记概念。

## 验收标准

1. 先说名字，再问「我叫什么」，Agent 答对  
2. 能说清：短期记忆 = 把历史 messages 再发给 API  
3. 能区分：scratchpad（一轮内）≠ 对话历史（跨轮）≠ 向量库（跨会话概念）  
4. 力扣 1 道（建议做）

---

## 长期记忆（概念一页）

以后做 RAG / Agent 时会碰到：

1. 把文档切成小块 → **Embedding** 成向量  
2. 存进 **向量库**（如 Chroma / FAISS）  
3. 用户提问 → 向量检索 top-k → 塞进 Prompt  

那叫**长期记忆**：程序关掉再开，仍能从库里捞出相关内容。  
今天**不用实现**；知道「短期靠 messages，长期靠检索」即可。
